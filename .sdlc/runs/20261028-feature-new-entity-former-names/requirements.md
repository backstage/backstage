# Requirements — feature-new — Entity former names and rename redirects

Run: `20261028-feature-new-entity-former-names` · Intent: `feature-new` · Source: `intent_brief.md` (Gate 0 approved 2026-10-28).
Upstream request: backstage/backstage#5231.

## Summary

An entity owner declares an entity's previous refs in a new well-known annotation. The catalog backend indexes
those refs in its existing search rows during stitching and exposes a permission-aware lookup that resolves a former
ref to the entity that currently claims it. The catalog client gains an optional method for that lookup. When the
catalog entity page or the TechDocs reader cannot find an entity by name, it asks the lookup, and on a hit replaces
the URL with the current entity's URL and shows a dismissible "renamed from" notice. No new tables or migrations.

## In scope

1. A new well-known annotation `backstage.io/former-names` in `@backstage/catalog-model`, with an exported constant
   and an exported parsing helper.
2. Indexing of the declared former refs into the catalog's existing search rows when an entity is stitched
   (`plugins/catalog-backend`).
3. A former-ref resolver in the catalog backend with the rules in FR-6 to FR-10, exposed as a REST endpoint in the
   OpenAPI spec, with the generated router (catalog-backend) and generated client (catalog-client) regenerated by the
   repo's own generator.
4. An optional `CatalogApi` method for the lookup in `@backstage/catalog-client`, implemented in `CatalogClient` and
   in the in-memory client; the matching optional method on the catalog-node `CatalogService` if that interface mirrors
   `CatalogApi`; mocks in catalog-node and catalog-react test utilities.
5. Redirect plus notice on the catalog entity page, in both the old (`core-*`) and new (`frontend-*`) frontend systems.
6. Redirect plus notice on the TechDocs reader route, keeping the sub-path inside the docs and the anchor, in both
   frontend systems where the reader page exists, reusing the existing redirect-notice component.
7. Tests: catalog-model unit tests; catalog-backend unit tests (indexing, resolver rules, permissions, router);
   catalog-client tests; jsdom component tests in plugin-catalog and techdocs.
8. Docs: `docs/features/software-catalog/well-known-annotations.md`, `docs/features/software-catalog/api.md`,
   `docs/features/techdocs/how-to-guides.md`; TSDoc on every new public symbol.
9. Changesets for every published package whose published output changes; regenerated API reports for every touched
   package.
10. Append `.sdlc/` to the root `.gitignore` (confirmed at Gate 0).

## Out of scope

1. Automatic detection of renames; any new database table, column or migration (`plugins/catalog-backend/migrations/**`
   is off-limits).
2. Any change to `plugins/techdocs-backend` or to the storage paths of already-built TechDocs.
3. Redirecting API calls made by entity name (e.g. `GET /entities/by-name/...` keeps returning 404 for an old name).
   Only the frontend pages redirect.
4. Rewriting relations or refs held by other entities that still point at the old name.
5. Hand-editing anything under `src/schema/openapi/generated/**` — it is regenerated only.
6. Any change to ESLint, Prettier or TypeScript configuration, `.claude/**`, `.cursor/**`, `AGENTS.md`, `.env*`,
   `.yarn/**`, `docs/releases/**`, or existing `.changeset/*` entries.

## Functional requirements

### catalog-model (`packages/catalog-model`)

- **FR-1** Export a constant for the annotation key `backstage.io/former-names`, placed and documented alongside the
  existing well-known `ANNOTATION_*` constants, with TSDoc marked `@public`.
- **FR-2** Export a parsing helper that takes an entity and returns the list of former refs it declares, as
  normalized (lower-cased, fully-qualified `kind:namespace/name`) entity ref strings:
  - the annotation value is a comma-separated list; entries are trimmed and empty entries are ignored;
  - a short ref (`name`, or `namespace/name`) takes the entity's own kind, and the entity's own namespace when no
    namespace is given (the default namespace applies when the entity has none), following ADR009 ref rules;
  - a malformed entry is skipped and never throws; a missing or empty annotation gives an empty list;
  - duplicates are removed, and an entry equal to the entity's own current ref is dropped.

### catalog-backend (`plugins/catalog-backend`)

- **FR-3** During stitching, for each normalized former ref returned by the FR-2 helper, write one row into the
  existing search table under a dedicated key that cannot collide with a real entity field path, using the existing
  search-row building code path. No new tables, columns or migrations.
- **FR-4** Indexing respects the search table's existing value-length and row conventions: an over-long ref is
  skipped rather than truncated into a different ref, and a malformed annotation never fails stitching of the entity.
- **FR-5** Rows for former refs are removed or replaced whenever the entity is re-stitched without them, exactly as
  other search rows are today.
- **FR-6 Real names win.** Before resolving, the resolver checks whether an entity currently exists with the requested
  ref as its real ref. That check ignores the caller's permissions (it also sees entities the caller cannot read). If
  such an entity exists, the resolver returns no redirect, even when another entity claims the ref.
- **FR-7 Ambiguous claims are refused.** The resolver counts the distinct entities that claim the ref, over all
  entities regardless of the caller's permissions. If more than one claims it, it returns no redirect. It logs nothing
  that names or counts the entities involved.
- **FR-8 Permissions apply.** When exactly one entity claims the ref and FR-6 does not apply, that entity is read
  through the normal `catalog.entity.read` permission check for the caller. A target the caller cannot read gives the
  same not-found result as no claim at all, so the response never reveals that an entity exists.
- **FR-9 Normal lookups stay fast.** The existing by-name, by-ref and by-uid paths are unchanged. The resolver is a
  separate method and endpoint, used only after a by-name miss, and it queries indexed search rows (no full scans
  of `final_entities`).
- **FR-10** Expose the resolver as a REST endpoint taking `kind`, `namespace` and `name` as path parameters, declared in
  `src/schema/openapi.yaml`. A hit responds 200 with the current entity (at least enough to build its ref and route);
  every miss — unknown ref, real-name match, conflict, or unreadable target — responds with the same 404 shape. The
  generated router in `src/schema/openapi/generated/` is regenerated with the repo's generator and the endpoint is
  wired in `createRouter.ts` with the same auth/credentials handling as the by-name endpoint.

### catalog-client and catalog-node (`packages/catalog-client`, `plugins/catalog-node`)

- **FR-11** Add an **optional** method to the `CatalogApi` interface that resolves a former entity ref (string or
  compound ref) to the current entity, or `undefined` on a 404. Existing implementers compile unchanged.
- **FR-12** Implement it in `CatalogClient` through the regenerated OpenAPI client
  (`src/schema/openapi/generated/`), passing request options (token) the same way `getEntityByRef` does.
- **FR-13** Implement it in the in-memory catalog client with the same FR-6/FR-7 rules (no permission model), and in the
  catalog-node `CatalogService` (optional) and its test mock, and in catalog-react's `catalogApiMock`, wherever those
  mirror `CatalogApi`.

### plugin-catalog (`plugins/catalog`)

- **FR-14** When the entity page's by-name lookup returns no entity (not an error other than not-found), and the
  `CatalogApi` implementation provides the optional method, call it once with the URL's ref. While it runs the page
  keeps its loading state; it does not flash "Entity not found".
- **FR-15** On a hit, navigate with `replace` to the current entity's route (via the existing entity route ref),
  keeping any sub-route below the entity (the tab path), the query string and the hash.
- **FR-16** On the new page, show a dismissible notice "This entity was renamed from `<old ref>`" (translated text,
  new keys in the package's translation ref). Dismissing hides it; a fresh load of the new URL does not show it.
- **FR-17** On a miss, or when the method is absent, show the existing "Entity not found" page unchanged.
- **FR-18** FR-14 to FR-17 hold in both the old frontend system (`CatalogEntityPage` / `useEntityFromUrl` /
  `EntityLayout`) and the new frontend system (`src/alpha` entity page and `EntityLayoutBui`).

### techdocs (`plugins/techdocs`)

- **FR-19** When the docs reader's entity lookup for `/docs/:namespace/:kind/:name/*` finds no entity, call the optional
  former-ref method; on a hit, navigate with `replace` to the same docs sub-path under the current entity, keeping the
  query string and the anchor (hash).
- **FR-20** Show the rename notice using the existing TechDocs redirect-notice component (`TechDocsRedirectNotification`)
  or its pattern, with translated text; a miss or an absent method keeps today's not-found behaviour.
- **FR-21** FR-19 and FR-20 hold for the reader page in both frontend systems (the alpha reader page reuses the same
  logic if it shares it).

### Docs, changesets, repo hygiene

- **FR-22** Document the annotation (format, short-ref defaults, the real-name and conflict rules, permissions) in
  `docs/features/software-catalog/well-known-annotations.md`, following `docs/contribute/doc-style-guide.md`.
- **FR-23** Document the new endpoint in `docs/features/software-catalog/api.md`.
- **FR-24** Document the TechDocs rename redirect in `docs/features/techdocs/how-to-guides.md`.
- **FR-25** Add new `.changeset/*.md` files (never edit existing ones) for every published package whose output

  (catalog-model 1.10.2, catalog-client 1.16.3, catalog-backend 4.0.3-next.0, catalog-node 2.2.7-next.0,
  catalog-react 4.0.0-next.0, catalog 2.0.11-next.0, techdocs 1.19.1-next.0). Messages are plain-language,
  adopter-facing, relevant to every package named, and name no internal code symbols. Check existing changesets for
  these packages first.
- **FR-26** Regenerate API reports (`report*.api.md`) for every touched package with the repo's command.
- **FR-27** Append a `.sdlc/` line to the root `.gitignore` without changing any existing line.

## Non-functional requirements

- **NFR-1 Style.** Each file matches its own package's existing conventions (see the run's `stack-profile.md`).
- **NFR-2 Headers.** Every new `.ts`/`.tsx` file starts with the Apache 2.0 header with year 2026; existing headers are
  untouched.
- **NFR-3 Non-breaking.** No existing public signature changes; the new `CatalogApi`/`CatalogService` method is optional.
- **NFR-4 Performance.** The by-name path is untouched; the resolver uses at most a small, fixed number of indexed
  queries per call.
- **NFR-5 No disclosure.** The 404 for every miss is identical; no log line names or counts conflicting claimants.
- **NFR-6 Generated code.** Files under `src/schema/openapi/generated/` are produced only by the repo's generator and
  match `openapi.yaml`.
- **NFR-7 Tests.** Fewer, thorough tests with multiple assertions; RTL tests use `screen` and `findBy*`, no test IDs.

## PII inventory

| Field                                      | Sensitivity                                        | Protection                                                              |
| ------------------------------------------ | -------------------------------------------------- | ----------------------------------------------------------------------- |
| Entity refs in `backstage.io/former-names` | Low (catalog metadata, same class as entity names) | Indexed like other annotations; read only through `catalog.entity.read` |
| Existence of a hidden entity at a ref      | Low–medium (information disclosure)                | FR-6/FR-8: all misses give the same 404; no logging of claimants (FR-7) |

No personal data is introduced.

## Role matrix

| Role                                                          | Resource                             | Action                                         |
| ------------------------------------------------------------- | ------------------------------------ | ---------------------------------------------- |
| Entity owner                                                  | catalog-info YAML of their entity    | Declare former refs in the annotation          |
| Catalog backend (stitcher)                                    | search rows                          | Write/replace former-ref rows during stitching |
| Any signed-in caller with `catalog.entity.read` on the target | former-ref endpoint                  | Resolve to the target entity                   |
| Caller without `catalog.entity.read` on the target            | former-ref endpoint                  | Gets 404, indistinguishable from no claim      |
| Frontend user                                                 | catalog entity page, TechDocs reader | Is redirected and sees the dismissible notice  |

## Acceptance criteria

- **AC-1** catalog-model tests cover: full refs, short refs (`name`, `namespace/name`) defaulting kind and namespace,
  whitespace and empty entries, malformed entries skipped, duplicates and self-ref removed, missing annotation.
- **AC-2** catalog-backend tests show former refs are written to search rows at stitch time (including short-form and
  malformed values) and are removed when the annotation is removed.
- **AC-3** catalog-backend tests show: a real name wins over a claim (also when the real-name entity is not readable by
  the caller); two claimants give no redirect; a single readable claimant resolves; an unreadable claimant gives
  not-found.
- **AC-4** A router test shows the endpoint returns 200 with the entity on a hit and the same 404 on each kind of miss.
- **AC-5** catalog-client tests show the method calls the endpoint and returns `undefined` on 404; the in-memory client
  applies the real-name and conflict rules.
- **AC-6** plugin-catalog jsdom tests (old and new frontend systems) show an old route redirects to the new one and
  shows the rename notice, and an unknown name still shows "Entity not found".
- **AC-7** techdocs jsdom tests show an old docs route redirects to the new docs route keeping sub-path and anchor and
  shows the notice, and an unknown name still shows the not-found state.
- **AC-8** `CI=1 yarn test <path>` passes for each touched package; `yarn tsc` passes; `yarn lint --fix` leaves no
  errors in touched files.
- **AC-9** API reports are regenerated for every touched package, and the generated OpenAPI files in catalog-backend and
  catalog-client match `openapi.yaml` (the repo's generator's check passes).
- **AC-10** New source files carry the Apache 2.0 header with year 2026; existing headers unchanged.
- **AC-11** Changesets exist for every published package touched, with the bumps in FR-25 and adopter-facing text.
- **AC-12** The docs pages in FR-22 to FR-24 describe the annotation, endpoint and TechDocs behaviour; `.gitignore`
