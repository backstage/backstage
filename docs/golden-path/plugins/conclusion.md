You now have a full-stack Backstage plugin with a backend API, persistent data,
a frontend interface, tests, and integrations with Backstage features. Use what
you learned to solve a validated problem for your developers rather than adding
plugins for their own sake.

## Find your next plugin

Before building another plugin, check the
[Backstage plugin directory](https://backstage.io/plugins) for an existing
solution that you can install or contribute to. Build a custom plugin when an
existing option does not meet your organization's needs.

## Develop plugins sustainably

Building the software is only the beginning. Use the Adoption Golden Path to
gather [stakeholder feedback](../adoption/004-first-stakeholder-feedback.md),
decide whether to [adopt or build](../adoption/005-customizing-your-instance.md#adopt-or-build),
and establish [plugin ownership](../adoption/007-plugin-ownership.md). These
practices help you decide what to improve, who will maintain the plugin, and
when an unsupported plugin should be retired.

## Continue the Golden Path

When your Backstage application is ready for production, continue with the
[Deployment Golden Path](../deployment/index.md).
