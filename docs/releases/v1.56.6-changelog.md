# Release v1.56.6

Upgrade Helper: [https://backstage.github.io/upgrade-helper/?to=1.56.6](https://backstage.github.io/upgrade-helper/?to=1.56.6)

## @backstage/plugin-api-docs@0.14.8

### Patch Changes

- 640f025: The AsyncAPI definition widget no longer resolves external references by default. References to whole external documents still render, with a placeholder naming the document that was not loaded; references that point into an external document (using a `#` fragment) fail to render with an error naming the reference. To resolve external references — for example to reach internal schema registries that require authentication — provide the `resolvers` prop to enable external reference resolution.

## @backstage/plugin-catalog-backend@4.0.4

### Patch Changes

- e26964d: Improved repository validation for catalog entity placeholders on Azure DevOps. Placeholder-driven reads on a configured Azure DevOps integration are now restricted to the entity's own repository on every Azure DevOps host shape, including legacy `{org}.visualstudio.com` hosts and Azure DevOps Server hosts, and targets that cannot be attributed to a repository are rejected as well.
- e6e35ab: Location annotations on entities submitted to the validate-entity endpoint can no longer override the location of the request.

## @backstage/plugin-kubernetes-backend@0.21.14

### Patch Changes

- fd7fe0c: Kubernetes proxy: stop forwarding the caller's `Authorization` and `Cookie` headers to the target cluster. Upstream requests now carry only credentials from the configured auth strategy or the `Backstage-Kubernetes-Authorization` header.

## @backstage/plugin-scaffolder-backend@4.2.5

### Patch Changes

- e33b6d9: Check the host that relative fetch URLs resolve to when user credentials are required.

  When `scaffolder.requireScmUserCredentials` is enabled, the fetch actions now apply the user-credential requirement to the host that the fetch URL resolves to, rather than the host of the template location. This makes the requirement effective also for fetch URLs that are not parseable as absolute URLs on their own.

## @backstage/plugin-scaffolder-backend-module-github@0.10.3

### Patch Changes

- b2d18d7: Validates the `targetPath` input of the `gitlab:repo:push`, `publish:gitlab:merge-request` and `publish:github:pull-request` scaffolder actions, and the `filesToDelete` entries of `publish:github:pull-request`. The values must be relative paths within the target repository; absolute paths and paths containing `..` segments are now rejected, so changes are only applied inside the intended subdirectory of the repository.
