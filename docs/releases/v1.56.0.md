These are the release notes for the v1.56.0 release of [Backstage](https://backstage.io/).

A huge thanks to the whole team of maintainers and contributors as well as the amazing Backstage Community for the hard work in getting this release developed and done.

## Highlights

### **BREAKING**: Filter predicates must be objects at the root

The `FilterPredicate` type, its zod schemas, and `parseFilterPredicate` in `@backstage/filter-predicates` now only accept objects at the root of a predicate. Primitive values such as `"component"` or `true` were previously accepted at the root, but no API that accepts filter predicates could match them in a meaningful way. Primitive values are still allowed as values to match against properties, and as the operand of `$contains` to match arrays of primitive values, for example `{ "metadata.tags": { "$contains": "java" } }`.

A new `AnyFilterPredicate` type describes predicates that may also be primitive values at the root, equivalent to the previous `FilterPredicate` type. The catalog backend now rejects entity and location queries with a primitive root value with an "Invalid query" error.

### **BREAKING**: Removed the Atlassian `usernameMatchingUserEntityName` sign-in resolver

The `usernameMatchingUserEntityName` sign-in resolver has been removed from `@backstage/plugin-auth-backend-module-atlassian-provider`, along with the `atlassianSignInResolvers` export that only contained it. Atlassian user profiles do not contain a username, so the resolver could never work. Use the `emailMatchingUserEntityProfileEmail` or `emailLocalPartMatchingUserEntityName` resolvers instead.

### **BREAKING PRODUCERS**: Backend instance IDs

The root instance metadata service now exposes an instance ID that is globally unique and stable for the lifetime of a running backend instance. Custom implementations and mocks of the service must now provide one. Each backend instance uses a random UUID by default, and you can supply your own through the new `instanceId` option of `createBackend` and `createSpecializedBackend`. The signals backend uses this ID to identify its event subscription, which lets deployments control how events fan out across instances.

### **BREAKING**: Incremental ingestion mark table upsert

The `ingestion_mark_entities` table in `@backstage/plugin-catalog-backend-module-incremental-ingestion` has a new `source_key` column and a unique constraint, so ingestion marks are now written with a single native upsert. This significantly reduces the number of database round trips during ingestion. The table's `ref` column is renamed to `entity_ref` as part of this change, which means the migration cannot be applied as part of a rolling, zero-downtime upgrade.

Contributed by [@Teo-ShaoWei](https://github.com/Teo-ShaoWei) in [#35177](https://github.com/backstage/backstage/pull/35177)

### Catalog filters with predicate queries

`EntityFilter` in `@backstage/plugin-catalog-react` has a new `getCatalogQuery` method, which lets filters express their backend constraints as a filter predicate. This supports logical operators such as `$any` and `$not`, as well as matchers like `$hasPrefix`, which could not be expressed with `getCatalogFilters`. All built-in filters now implement it, and `getCatalogFilters` is deprecated. The `EntityListProvider` combines the predicates of all active filters into a single query, and the catalog export button and `TechDocsPicker` respect them too.

This requires a catalog backend from Backstage release 1.49 or later. Note that when not paginating, entities are now fetched using `streamEntities` instead of `getEntities`, so tests that mock `getEntities` for an `EntityListProvider` need to mock `streamEntities` instead. An `EntityOrderFilter` that orders by a field that some entities lack now excludes those entities, consistent with paginated mode. `EntityTagFilter` with multiple tags now requires all of them, and `EntityUserFilter.starred` matches full entity refs.

The `InMemoryCatalogClient` test utility in `@backstage/catalog-client` now matches entities the same way as the catalog backend, which may change the outcome of existing tests. For example, relation shorthand now works in `query`, and field keys are matched case-insensitively.

### New CLI modules for catalog, scaffolder, and search

Three new CLI modules provide domain-oriented commands that talk directly to the corresponding plugin APIs:

- `@backstage/cli-module-catalog`: `catalog list`, `catalog get`, `catalog validate`, `catalog register`, `catalog unregister`
- `@backstage/cli-module-scaffolder`: `template list`, `template execute`, `template dry-run`
- `@backstage/cli-module-search`: `search`, `docs search`

Commands that list results support `--output human` or `--output json`, along with `--limit` and `--cursor` for paging. `catalog validate` and `template dry-run` exit with a non-zero code when the input is invalid, making them a good fit for CI pipelines.

Contributed by [@yangcao77](https://github.com/yangcao77) in [#34952](https://github.com/backstage/backstage/pull/34952)

### TechDocs engine abstraction

TechDocs now has an engine abstraction layer that paves the way for documentation engines other than MkDocs. This introduces an `--engine` flag in the TechDocs CLI, an engine configuration map, a generator registry with support for the `backstage.io/techdocs-engine` annotation, an `engine` field in `techdocs_metadata.json`, and a `serve:raw` command. MkDocs remains the default with no change in behavior. The built-in generator is now registered as `mkdocs`, with `techdocs` kept as an alias, and `serve:mkdocs` and the `--mkdocs-parameter-*` flags now print deprecation warnings.

Contributed by [@byan1197](https://github.com/byan1197) in [#35781](https://github.com/backstage/backstage/pull/35781)

### TechDocs improvements

TechDocs now uses the app's `NotFoundErrorPage` when documentation is missing, so any override you have provided is used there as well. Contributed by [@brentswisher](https://github.com/brentswisher) in [#34523](https://github.com/backstage/backstage/pull/34523)

A new `withoutFeedbackLink` option on the `page:techdocs/reader` and `entity-content:techdocs` extensions lets you hide the feedback button. Contributed by [@benjidotsh](https://github.com/benjidotsh) in [#35011](https://github.com/backstage/backstage/pull/35011)

The TechDocs backend now registers a `get-techdocs-metadata` action with the actions registry, controlled by a new `techdocs.actions.read` permission. Contributed by [@thenmozhi-loganathan](https://github.com/thenmozhi-loganathan) in [#33412](https://github.com/backstage/backstage/pull/33412)

TechDocs addons now render in apps using the new frontend system, contributed by [@GabDug](https://github.com/GabDug) in [#35770](https://github.com/backstage/backstage/pull/35770). Addons also load in individual Suspense boundaries, content no longer flashes before styles load, and Material UI styles for addons work in module-federated apps.

### Catalog backend reliability and performance

The catalog backend has received a number of reliability fixes for stitching. Successfully processed entities no longer remain unavailable if stitch scheduling is interrupted, pending stitching work is no longer lost when entities are deleted and re-added, and failing entities are retried with increasing delays. Non-positive stitching polling intervals and lease durations are now rejected at startup.

Entities no longer disappear from filtered and sorted catalog queries after a database error during stitching, since the final entity and its search index rows are now written together in one transaction. Contributed by [@bitflicker64](https://github.com/bitflicker64) in [#35815](https://github.com/backstage/backstage/pull/35815)

Orphan entity cleanup is faster and more stable on large PostgreSQL catalogs, large entity provider mutations and projected list reads now yield to the event loop, and LDAP organization ingestion is faster for large directories.

### Database connection pool defaults

The backend no longer issues periodic per-plugin database keepalive queries by default, and the default minimum PostgreSQL and MySQL connection pool size is now zero. Idle connections can now be retired after the configured timeout, while explicitly configured pool minimums are preserved. Set `backend.database.keepalive: true` to keep the previous behavior.

Contributed by [@hudsonb](https://github.com/hudsonb) in [#35366](https://github.com/backstage/backstage/pull/35366)

### Experimental connections service

Backends created with `createBackend` now provide the experimental connections service by default. Plugins and modules can declare connection dependencies using `declareConnection` and request the service via `connectionsServiceRef`, both from `@backstage/backend-plugin-api/alpha`. Test backends also provide the service.

Contributed by [@neoreddog](https://github.com/neoreddog) in [#36050](https://github.com/backstage/backstage/pull/36050)

### Signals WebSocket authentication

The signals WebSocket endpoint now requires a valid user identity token. Connections without a token, with an invalid token, or with a service token are rejected, and unauthenticated guest connections are no longer accepted. On the frontend, the signals client now shares one WebSocket connection across simultaneous subscriptions, and does not connect when no identity token is available.

Contributed by [@ciiay](https://github.com/ciiay) in [#34898](https://github.com/backstage/backstage/pull/34898)

### Featured templates home page widget

The scaffolder plugin now provides a `Featured Templates` home page widget that displays templates tagged with a configurable catalog tag, defaulting to `featured`.

Contributed by [@benjidotsh](https://github.com/benjidotsh) in [#35572](https://github.com/backstage/backstage/pull/35572)

### Swappable user avatar

The org plugin now has a swappable `UserAvatar` component, used for user profile pictures across the org plugin.

Contributed by [@nikolarAutodesk](https://github.com/nikolarAutodesk) in [#34748](https://github.com/backstage/backstage/pull/34748)

### Secure GitLab token actions

The `gitlab:projectAccessToken:create` and `gitlab:projectDeployToken:create` scaffolder actions have a new `variableKey` input. When provided, the generated token is stored directly as a masked GitLab CI/CD variable instead of being exposed in task outputs and checkpoint state. The raw token outputs are now deprecated when `variableKey` is not used.

Contributed by [@djanickova](https://github.com/djanickova) in [#35769](https://github.com/backstage/backstage/pull/35769)

### Backstage UI updates

Backstage UI has updated to React Aria Components 1.22.0. `MenuSection` no longer accepts `disabledKeys`, so move it to `Menu` or set `isDisabled` on the affected `MenuItem` components. Programmatic clicks on `Checkbox` and `Switch` labels no longer toggle their selection. Contributed by [@Naycon](https://github.com/Naycon) in [#36090](https://github.com/backstage/backstage/pull/36090)

A new `theme` CSS cascade layer sits between `components` and `utilities`, giving apps a place for brand overrides that win over component styles without raising specificity. Contributed by [@serahkiburu](https://github.com/serahkiburu) in [#36138](https://github.com/backstage/backstage/pull/36138)

`Combobox` keyboard selection while filtering has been fixed, contributed by [@antony-bouyon](https://github.com/antony-bouyon) in [#35970](https://github.com/backstage/backstage/pull/35970). The `--bui-bg-app` token now follows the page's `color-scheme` until a theme mode is set, contributed by [@carlerikjohan](https://github.com/carlerikjohan) in [#36165](https://github.com/backstage/backstage/pull/36165).

Check the [BUI Changelog](https://ui.backstage.io/changelog) for more details.

- The catalog graph and catalog import pages in the new frontend system now use the page header provided by the app. Contributed by [@denesbeck](https://github.com/denesbeck) in [#36067](https://github.com/backstage/backstage/pull/36067) and [#36068](https://github.com/backstage/backstage/pull/36068).

- `streamEntities` no longer asks the catalog backend to compute the total number of matching items, and its `totalItems` option is deprecated.
- Fixed catalog processing error messages to report stable processor names in minified builds. Contributed by [@vinzscam](https://github.com/vinzscam) in [#35760](https://github.com/backstage/backstage/pull/35760).

- `@backstage/catalog-model` now uses version 4 of `zod`. If your own packages use `zod` without declaring it as a dependency, make sure to add it to their `package.json`.
- Config schemas now compile in roughly half the time, which speeds up backend startup.
- Reading a number from an empty or whitespace-only config value now fails with a clear error instead of returning `0`. Contributed by [@suletetes](https://github.com/suletetes) in [#35773](https://github.com/backstage/backstage/pull/35773).

- The `auth.providers.guest` configuration is now visible to frontend plugins. Contributed by [@JessicaJHee](https://github.com/JessicaJHee) in [#35766](https://github.com/backstage/backstage/pull/35766).
