## @backstage/core-plugin-api@1.13.0-next.3

### Minor Changes

- 558c076: Exported the alpha `TranslationRefTuple` type for messages selected by calling a translation ref. Refs are now callable functions; treat them as opaque values.

  **BREAKING PRODUCERS**: Translation snapshots require `t` even when `ready` is false. Custom translation APIs must provide a translator using available messages and language fallbacks.

### Patch Changes

- Updated dependencies
  - @backstage/frontend-plugin-api@0.19.0-next.3

## @backstage/frontend-plugin-api@0.19.0-next.3

### Minor Changes

- 806a9cf: **BREAKING**: Removed the `/alpha` entry point. All of its exports are already available from `@backstage/frontend-plugin-api`; update imports to use the main entry point instead:

  ```diff
  -import { PluginWrapperBlueprint } from '@backstage/frontend-plugin-api/alpha';
  +import { PluginWrapperBlueprint } from '@backstage/frontend-plugin-api';
  ```

  The exported APIs retain the same behavior and identity. For the deprecated `pluginWrapperApiRef`, prefer `coreApis.pluginWrapper` from the main entry point.

- 0f2ffc9: **BREAKING**: Removed the `ProgressProps` type. Replace imports and usages of this type with its existing shape, `{}`. The `Progress` component and its props contract are unchanged.
- 7285912: **BREAKING PRODUCERS**: `TranslationSnapshot` now requires `t` even when `ready` is false. Custom `TranslationApi` implementations must provide a translator using available messages and language fallbacks.

### Patch Changes

- d47986a: Improved type inference for deeply nested and cyclic translation messages. Required replacement values and plural counts are inferred at any depth, and count interpolation requires a numeric value.
- 6928d62: Fixed swappable components losing their mounted state when their props change. The resolved component remains stable while its props update.
- 641ac02: Added `coreExtensionData.titleTranslation` to provide a translation message selection alongside a static title. Consumers can opt in to translated titles. The selection must not require formatting values.
- 7594fd4: Page and sub-page blueprints now accept typed translation message selections in their `title` parameter, using existing translation resources. Select a message by calling a translation ref, for example `myTranslationRef('page.title')`. TypeScript checks the key and rejects messages that require formatting values.

  Resolved translations take precedence over configured titles in every language, including the default language. Titles wait for the selected language on first load and retain resolved values during later loads or failures, preserving page state.

  `TranslationRef` values are now callable functions. Treat refs as opaque values rather than checking for plain objects or cloning them.

## @backstage/plugin-events-backend-module-azure@0.3.0-next.3

### Minor Changes

- 70fd46d: **BREAKING** Webhook events modules now require a webhook secret by default. Requests to the `/api/events/http/github`, `/api/events/http/gitlab`, and `/api/events/http/azureDevOps` endpoints are rejected with HTTP 403 when no webhook secret is configured, instead of being accepted without validation. To continue accepting unauthenticated events, for example in development environments, set the module's new `dangerouslyAllowUnauthenticatedEvents` option to `true`. ## @backstage/core-components@0.18.16-next.2

### Patch Changes

- 1c75912: Deprecated components with Backstage UI replacements or compositions: `Avatar`, `Link`, `LinkButton`, `Select`, `Content`, `BottomLink`, `HeaderActionMenu`, `HeaderLabel`, `HeaderTabs`, `ItemCardGrid`, `ItemCardHeader`, `TabbedCard`, `CardTab`, `SubvalueCell`, `CreateButton`, `ContentHeader`, `FavoriteToggle`, `FavoriteToggleIcon`, `HeaderIconLinkRow`, `IconLinkVertical`, and `OverflowTooltip`, along with their associated public types.

  Use the replacements from `@backstage/ui` described in each component's deprecation notice. These migrations require adapting props and composition, including external-link presentation, selection callbacks, document titles, and error boundaries where applicable. Existing exports and runtime behavior are unchanged.

- 7890ec2: Deprecated legacy page shells (`Page`, `PageWithHeader`, `Header`), routed tabs (`TabbedLayout`, `TabbedLayout.Route`, `RoutedTabs`), `AlertDisplay`, `AppIcon`, the named icon wrappers, and their associated public types for new frontend development. Existing exports and behavior remain available, including in migrated plugins.

  Use page and sub-page extensions and `PageLayout` from `@backstage/frontend-plugin-api` for framework-managed pages, or compose `@backstage/ui` headers and tabs with explicit routing for standalone layouts. Legacy themes, arbitrary header content, document titles, and focus behavior need deliberate migration. Rely on the new frontend app's existing alert/toast display. For app-customizable icons, use `useApi(coreApis.icons).icon(key)` from `@backstage/frontend-plugin-api` and render the returned element, handling missing icons as needed.

## @backstage/plugin-catalog-backend-module-bitbucket-cloud@0.5.17-next.3

### Patch Changes

- ed1cb3e: The Bitbucket Cloud entity provider now finds catalog files with the workspace code search API of Bitbucket Cloud, because Bitbucket Cloud removes the old code search API on 2026-11-15. The provider finds the same locations for the same configuration.

  The new API needs a credential that identifies a user, for example an Atlassian account email as `username` with an API `token`. The token needs the scopes `read:repository:bitbucket` and `read:workspace:bitbucket`. The old API did not need `read:workspace:bitbucket`. Bitbucket Cloud rejects app passwords for this API, so if your integration uses `appPassword`, change it to an API token.

- Updated dependencies
  - @backstage/integration@2.2.0-next.1
