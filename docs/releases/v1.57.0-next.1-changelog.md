## @backstage/frontend-app-api@0.17.0-next.1

### Minor Changes

- 8c6c842: **BREAKING**: Removed the deprecated `createSpecializedApp` and `CreateSpecializedAppOptions` exports. Use `prepareSpecializedApp(options).finalize()` and `PrepareSpecializedAppOptions` instead. For sign-in or asynchronous session preparation, render the bootstrap app and subscribe with `onFinalized()` instead of calling `finalize()`.

  Replace `advanced.apis` with `advanced.sessionState` from a previously finalized app to reuse its APIs, identity, and predicate context. Register custom APIs through `ApiBlueprint` extensions rather than passing an arbitrary API holder. Pass a supplied config API through the top-level `config` option. To reuse an identity supplied through the API holder, configure a sign-in page that calls `onSignInSuccess(identityApi)` and use the bootstrap/`onFinalized()` flow; an `ApiBlueprint` cannot override the app's identity proxy.

### Patch Changes

- d514e4d: Updated app options to use the `ExtensionFactoryMiddleware` type from `@backstage/frontend-app-api` instead of the deprecated export from `@backstage/frontend-plugin-api`. Middleware behavior is unchanged.
- e55a4a8: Updated plugin identity handling to use `pluginId`, while preserving support for older plugin instances that only expose `id`.
- c147b7a: Fixed disabled external route bindings falling back to their default targets during link resolution.

  Navigation analytics now use the most specific routed extension even when it has no route reference, including nested extensions with an empty path.

## @backstage/frontend-plugin-api@0.19.0-next.1

### Minor Changes

- d514e4d: **BREAKING**: Removed the deprecated `ExtensionFactoryMiddleware` type export. Import it from `@backstage/frontend-app-api` instead:

  ```diff
  -import type { ExtensionFactoryMiddleware } from '@backstage/frontend-plugin-api';
  +import type { ExtensionFactoryMiddleware } from '@backstage/frontend-app-api';
  ```

  Add `@backstage/frontend-app-api` as a dependency of your app package if it is not already declared. Middleware behavior is unchanged.

- 62268a9: **BREAKING**: Removed the deprecated `AnalyticsImplementationBlueprint` and `AnalyticsImplementationFactory` exports. Import them from `@backstage/plugin-app-react` instead. No changes to their usage are needed beyond updating the imports.
- 86ff5a3: Removed the deprecated `PageTab` and `PluginOptions` types. Use `PageLayoutTab` and `CreateFrontendPluginOptions` instead.
- dafdab8: **BREAKING**: Removed the deprecated `withApis` export. Wrap class components in a function component that uses `useApi` instead:

  ```tsx
  import { errorApiRef, useApi } from '@backstage/frontend-plugin-api';
  import { MyClassComponent, MyClassComponentProps } from './MyClassComponent';

  export function MyComponent(props: Omit<MyClassComponentProps, 'errorApi'>) {
    const errorApi = useApi(errorApiRef);
    return <MyClassComponent {...props} errorApi={errorApi} />;
  }
  ```

- e55a4a8: **BREAKING**: Removed the deprecated `FrontendPlugin.id` property from the public interface. Use `pluginId` instead. The runtime alias is retained for compatibility with older apps.
- d84cf73: Removed the deprecated `DialogApi.show`, `DialogApi.showModal`, and `IconsApi.getIcon` methods. Use `DialogApi.open` with your own dialog presentation, and `IconsApi.icon` to retrieve icon elements.

  The API references now use `core.dialog.v2` and `core.icons.v2`. Upgrade `@backstage/plugin-app` alongside this package, and update custom API implementations to use the new references.

## @backstage/frontend-test-utils@0.7.0-next.1

### Minor Changes

- 76b1c3d: Removed the deprecated standalone mock API type exports. Use the corresponding `mockApis` helpers to create instances and derive types as follows:

  | Removed type                 | Replacement type                                                     |
  | ---------------------------- | -------------------------------------------------------------------- |
  | `MockAlertApi`               | `ReturnType<typeof mockApis.alert>`                                  |
  | `MockAnalyticsApi`           | `ReturnType<typeof mockApis.analytics>`                              |
  | `MockConfigApi`              | `ReturnType<typeof mockApis.config>`                                 |
  | `MockErrorApi`               | `ReturnType<typeof mockApis.error>`                                  |
  | `MockFeatureFlagsApi`        | `ReturnType<typeof mockApis.featureFlags>`                           |
  | `MockFetchApi`               | `ReturnType<typeof mockApis.fetch>`                                  |
  | `MockPermissionApi`          | `ReturnType<typeof mockApis.permission>`                             |
  | `MockStorageApi`             | `ReturnType<typeof mockApis.storage>`                                |
  | `MockTranslationApi`         | `ReturnType<typeof mockApis.translation>`                            |
  | `MockErrorApiOptions`        | `NonNullable<Parameters<typeof mockApis.error>[0]>`                  |
  | `MockFeatureFlagsApiOptions` | `NonNullable<Parameters<typeof mockApis.featureFlags>[0]>`           |
  | `ErrorWithContext`           | `ReturnType<ReturnType<typeof mockApis.error>['getErrors']>[number]` |

  Import `mockApis` from `@backstage/frontend-test-utils`. For example, use `mockApis.analytics()` to create an analytics mock and `ReturnType<typeof mockApis.analytics>` when you need an explicit instance type. Existing calls to the helpers require no changes. Inspection methods such as `getEvents`, `getErrors`, and `getAlerts`, along with legacy alert support, remain available. `MockFetchApiOptions` remains exported for configuring `mockApis.fetch`.

- 53ab1aa: **BREAKING**: `renderInTestApp`, `renderTestApp` and `createExtensionTester` now throw for every error reported while creating the test app or extension tree, including the ones a real app only logs as warnings, such as `EXTENSION_IGNORED`. Previously `renderInTestApp` and `renderTestApp` ignored these errors, so a test could pass for an app that is broken. All three helpers accept a new `isExpectedError` option to allow specific errors.

  **Migration:** fix the reported error in the test setup. The error message names the code to allow if the error is expected:

  ```ts
  renderInTestApp(<MyComponent />, {
    isExpectedError: error =>
      error.code === 'EXTENSION_INPUT_DATA_IGNORED' &&
      error.context.node.spec.id === 'page:my-plugin',
  });
  ```

  A common one is `API_FACTORY_CONFLICT` from providing an API that another plugin owns, such as a `core.*` API passed in `extensions`. That override was always rejected, so remove it, or use the `apis` option to replace an API in a test.

- e3d50c4: Removed the deprecated `show` and `showModal` methods from dialog test helpers, and `getIcon` from icons test helpers. Update tests to use `open` for dialogs and `icon` for icon elements.

### Patch Changes

- f81ca4e: The AWS S3 URL reader no longer assumes the configured `roleArn` a second time when the matching account under `aws.accounts` already provides credentials for that exact role, for example through a web identity token file. Previously the role had to trust itself for this setup to work. The role is still assumed explicitly when the integration sets an `externalId`.
- 9fc68ae: Fixed the `valkey` cache store sharing keys between plugins. Two plugins that cached a value under the same key could read and overwrite each other's entries. Keys are now stored under the plugin namespace, the same way the `redis` store does it. Cache entries now use new key names, so existing entries are no longer read and are rebuilt as plugins write new values. Old entries stay in Valkey until their TTL expires. Entries without a TTL, and the per-plugin key index sets that the old layout created, stay until you remove them manually.

## @backstage/create-app@0.9.4-next.1

### Patch Changes

- 04a54e2: Bumped TypeScript in the app templates to `~5.9.0`.
- b8777d1: New apps now support Node.js 24 and 26, in line with the [versioning policy](https://backstage.io/docs/overview/versioning-policy#nodejs-releases). The `engines` field in the app template is set to `^24.15.0 || ^26.13.0`, and creating a new app now requires Node.js 24 (24.15.0 or later) or Node.js 26 (26.13.0 or later). 24.15.0 is the lowest version that all dependencies support, and 26.13.0 is the first Node.js 26 LTS release.

  To update an existing app, set `engines.node` in your root `package.json` to `^24.15.0 || ^26.13.0`, and update the Node.js version used in your CI workflows and `Dockerfile` if needed.

  If your `yarn.lock` resolves `avsc` to a version older than 5.7.8, run `yarn up -R avsc`. Those versions crash on load on Node.js 25 and later, which breaks Jest tests that import the AsyncAPI widget from `@backstage/plugin-api-docs`. If it resolves `node-gyp` to 12.3.0, run `yarn up -R node-gyp`, since that version can't download Node.js headers through a proxy on Node.js 26.
