## @backstage/frontend-test-utils@0.7.0-next.1

### Minor Changes

- 53ab1aa: **BREAKING**: `renderInTestApp`, `renderTestApp` and `createExtensionTester` now throw for every error reported while creating the test app or extension tree, including the ones a real app only logs as warnings, such as `EXTENSION_IGNORED`. Previously `renderInTestApp` and `renderTestApp` ignored these errors, so a test could pass for an app that is broken. All three helpers accept a new `isExpectedError` option to allow specific errors.

  **Migration:** fix the reported error in the test setup. The error message names the code to allow if the error is expected:

  ```ts
  renderInTestApp(<MyComponent />, {
    isExpectedError: error =>
      error.code === 'EXTENSION_INPUT_DATA_IGNORED' &&
      error.context.node.spec.id === 'page:my-plugin',
  });
  ```

  A common one is `API_FACTORY_CONFLICT` from providing an API that another plugin owns, such as a `core.*` API passed in `extensions`. That override was always rejected, so remove it, or use the `apis` option to replace an API in a test.

## @backstage/plugin-catalog-backend-module-incremental-ingestion@0.9.1-next.1

### Patch Changes

- 7baaad7: Fixed incremental ingestion getting stuck when a provider emits the same entity more than once in a single page or event. Since the previous release, this made every attempt to ingest that page fail on PostgreSQL with `ON CONFLICT DO UPDATE command cannot affect row a second time`, so the provider never got past it. Now only the last copy of each entity is kept. A warning names the provider and some of the repeated entity refs, at most once every 10 minutes per provider.

  Providers should still emit each entity at most once per page. If the copies differ and arrive in a different order on each run, the stored entity can change on every run.

- Updated dependencies
  - @backstage/plugin-catalog-backend@4.0.3-next.1
  - @backstage/plugin-events-node@0.5.0-next.1
  - @backstage/plugin-catalog-node@2.2.7-next.1
