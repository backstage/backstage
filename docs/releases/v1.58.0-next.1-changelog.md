# Release v1.58.0-next.1

Upgrade Helper: [https://backstage.github.io/upgrade-helper/?to=1.58.0-next.1](https://backstage.github.io/upgrade-helper/?to=1.58.0-next.1)

## @backstage/integration@2.4.0-next.1

### Minor Changes

- 1f44c7e: SCM URLs whose repository, owner, or reference parts contain path traversal or URL query and fragment delimiter sequences are now rejected by the SCM URL helpers, and the Bitbucket Cloud and Server default branch lookups now apply the same validation.

### Patch Changes

- b053d1b: Gitea location URLs are now rejected when their repository path contains traversal sequences or URL query and fragment delimiters.
- 84bf4e5: The Gerrit and Bitbucket Cloud URL readers now derive the base of their request URLs from the parsed URL rather than from the raw URL string.
- 42de49e: When `allowedInstallationOwners` is configured for a GitHub App, installations owned by other accounts are now left out when enumerating the app's installations. This makes the enumeration consistent with how the list is already enforced when installation tokens are issued, so that consumers deriving organizations from the app's installations, such as catalog providers, only see the allowed ones.
- c6ca344: When `allowedInstallationOwners` is configured for a GitHub App, the `publicAccess` token fallback now only mints its token from an installation owned by one of the allowed accounts, instead of using the first available installation. This makes the fallback consistent with how the list is already enforced when installation tokens are issued, so that the fallback is always served by an installation within the allow list.

## @backstage/plugin-scaffolder-react@3.1.0-next.1

### Minor Changes

- 4595cd3: The review step now masks a field whenever any parameter step marks it as a password or secret, or sets a review mask for it. This includes steps hidden by a `when` condition, and no longer depends on which step declares the field first.

  Custom review step components now also receive the complete form state as `schemaFormState` and all parameter steps, including hidden ones, as `allSteps`. Forward these to `ReviewState` as `schemaFormState` and `maskSchemas` to keep the same masking behavior as the built-in review step. The steps passed to custom review step components are now typed with their `title`, so they can be passed to `ReviewState` as `schemas` without a type error. Code that builds these props by hand, for example in tests, now needs to include a `title` for each step.

### Patch Changes

## @backstage/plugin-scaffolder-backend-module-gitlab@0.12.5-next.1

### Patch Changes

- 91f7410: Fixed `publish:gitlab:merge-request` failing with `The branch creation failed because the branch already exists at: ...` when a scaffolder task is retried with experimental task recovery enabled. A retried task now reuses the branch and the merge request that its first attempt created, instead of failing at a step that had already done its job, and it no longer tries to create a branch that was deleted in between.
