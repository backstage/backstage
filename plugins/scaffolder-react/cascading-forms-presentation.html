What Was Built

  • Reactive conditional rendering — if/then/else and dependencies keywords drive field visibility
  • Dependent dropdown filtering — parent field changes update child field options within 200ms
  • Async option loading — optionsLoader fetches data from Backstage APIs with 300ms debounce
  • Value preservation — unmounted field values restored on remount
  • Error boundaries — per-field isolation prevents cascading crashes
  • Analytics tracking — load, success, and error events via Backstage analytics API

Why — Template Author Productivity

  • Before: Static forms only — every field always visible regardless of context
  • After: Dynamic forms — fields appear/disappear based on sibling values
  • Impact: Fewer wizard steps, less user confusion, richer template logic

Risks and Mitigations

Risk Severity Mitigation
Performance with complex schemas (>20 branches) Medium resolveConditionalSchema is pure/sync with <50ms target; MAX_DEPTH=50 prevents stack overflow
RJSF version coupling (5.24.13) Medium Zero RJSF core modifications; all customization through documented extension points
Infinite render loops from schema changes High useConditionalSchema uses structural equality caching; handleChange has JSON equality bail-out
optionsLoader network failures Low Per-field error boundary + retry button + AbortController cleanup on unmount
Memory leaks from field mount/unmount cycles Low mountedRef guard + AbortController + clearTimeout in useOptionsLoader cleanup
