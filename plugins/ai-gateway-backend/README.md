# AI gateway backend

An HTTP facade over the alpha Backstage AI models service, so that frontend code can use the models that the operator has configured under `ai.providers`. Provider API keys stay on the backend. Callers must be signed-in users, and the plugin never sees or forwards any credentials other than the user's Backstage token.

## Installation

Install the plugin in your backend package.

```bash
yarn --cwd packages/backend add @backstage/plugin-ai-gateway-backend
```

```ts title="packages/backend/src/index.ts"
backend.add(import('@backstage/plugin-ai-gateway-backend'));
```

The plugin depends on the `aiModels` service, so you also need to configure at least one provider under `ai.providers`. See the [AI models service documentation](../../docs/backend-system/core-services/ai-models.md).

## Endpoints

All endpoints are served under `/api/ai-gateway` and are described in [`src/schema/openapi.yaml`](./src/schema/openapi.yaml).

| Endpoint                   | Description                                                                              |
| -------------------------- | ---------------------------------------------------------------------------------------- |
| `POST /v1/generate/text`   | Returns `{ text, finishReason, usage }`.                                                 |
| `POST /v1/generate/object` | Takes a JSON Schema in `schema` and returns `{ object, finishReason, usage }`.           |
| `POST /v1/generate/stream` | Streams text as server-sent events: `text`, then `done`, or `error` if the stream fails. |

Requests accept `provider`, `model`, `system`, and exactly one of `prompt` or `messages`.

## Permissions

Each request is authorized with the `ai.gateway.invoke` permission, which is exported as `aiGatewayInvokePermission`. Without a permission policy this is allowed for all signed-in users, so add a policy rule if you want to restrict who can spend your model budget.

## Configuration

```yaml
aiGateway:
  # Max characters across the system prompt, prompt, and messages. Default 100000.
  maxInputCharacters: 100000
  # Max characters in the JSON Schema of an object request. Default 20000.
  maxSchemaCharacters: 20000
  # Max tokens generated by a single request. Default 4096.
  maxOutputTokens: 4096
```

Requests over the limits are rejected with a `400` response. If no AI provider is configured, requests fail with `503`.

## Security notes

- The JSON Schema is not validated against the model's output on the server, so clients must validate the returned object.
- Errors from the upstream AI provider are never sent to the client, as they can contain prompt contents. Clients receive a generic `503` message instead.
- Logs contain the user, provider, model, and token usage, never prompts or generated text.
