`package bundle` now supports pnpm projects. The bundle gets its own `pnpm-workspace.yaml` with `nodeLinker: hoisted`, the `overrides` of the project, and the settings that decide where pnpm caches packages and what the lockfile resolves to, including patch files and pnpmfiles. A missing patch file fails the command. An entry in `overrides` that refers to a root dependency with `$name` gets the range of that dependency, since the bundle doesn't have it. The registry settings of the root `.npmrc` file are copied as well. The user, password, and query string of registry URLs are left out, also in `pnpm-workspace.yaml`, and the path is kept. Registry URLs with `${VAR}` placeholders are left out, since pnpm ignores them in project settings. Auth settings are not copied. The command warns when the pnpmfile seems to load a package that isn't installed where the bundle is written, and removes an `.npmrc` file or pnpmfile that an earlier bundle left in the target directory. The seeded `pnpm-lock.yaml` is pruned and installed offline. When the pnpm cache lacks a package, the command fails and names the package and the settings that decide where pnpm looks for it.
