---
'@backstage/ai-node': minor
---

Added a new `@backstage/ai-node` package with an alpha, plugin-scoped AI service that gives backend plugins a managed, low-level agent primitive: each plugin chooses its own configuration path in app-config, sessions are bound to their original owner, and callers acquire reference-counted handles whose release never cancels admitted work. Model dispatch is guarded per attempt — permission, lease fencing, and credential identity are rechecked before any provider request, and every decision and outcome is recorded in a durable, redacted audit journal. Plugins can persist agent sessions in their existing PostgreSQL or file-backed SQLite database and recover committed state after a backend restart, with fenced writes that prevent expired or superseded owners from changing a session. Organization- and service-scoped provider credentials can be supplied as read-only secrets from app-config, users can store personal provider credentials encrypted in the Backstage database with concurrent updates and OAuth refreshes serialized across replicas, and an installation-scoped `ai` config section supplies the canonical model catalog and credential precedence, with every missing entry failing closed as a journaled, actionable denial instead of a fallback.

Providers are registered as trusted in-process modules whose operations the guard certifies; Google Gemini and Vertex models dispatch through a guarded worker transport that confines credentials and network access and settles in-flight work on worker loss. Guarded, journaled OAuth credential refresh machinery exists internally for Anthropic and OpenAI token endpoints, but the wiring that would run it automatically before a dispatch is not exposed by the package's public or alpha API: in the shipped configuration an expired OAuth credential fails closed with an actionable denial instead of being refreshed, and publicly configurable pre-dispatch refresh is future work. Hosts can expose the managed service over HTTP through a support surface that enforces session ownership, model listing, and audit-read permissions. Fail-closed boundaries to be aware of: AWS Bedrock models are not supported and fail closed; the Codex adapter dispatches over SSE only, with the WebSocket and automatic transports denied; and user-scope encrypted personal credentials are stored per plugin instance, so a user's personal credentials saved through one plugin are not shared with another plugin's instance.

Hosts wiring the integration can inject an event emitter that receives typed events, best-effort, for guarded attempts and lease and journal activity — denials, dispatched operations, and lease activity — through a single subscriber. Best-effort means invalid or secret-shaped identifiers and throwing subscribers are dropped rather than fail the observed operation, and a denial's event reason code can differ from the journal's (a resolver denial deliberately reports a fixed resolution-failed code). Events have no payload or credential fields and carry identifiers, counts, reason codes, and durations; the identifiers are host-trusted, the same trust caveat the audit journal gives its session references, so a subscriber can count and alert on activity without dedicated payload or credential fields.

Code mode is disabled by default; hosts wiring the integration enable it with an option, and it runs model-written JavaScript in a QuickJS sandbox with no access to the network, filesystem, timers, or host modules, and survives restarts by deterministic replay. A host wall-clock ceiling per script execution (default five minutes; a script's own declared timeout may lower it, never exceed it) and an optional memory limit bound runaway scripts; output, script store writes, and replay journaling grow with the results a script's nested calls deliver. Model calls from inside scripts route through the same guarded facade as any other dispatch, with the per-attempt permission, fence, and credential recheck. Code mode's own durable journal lives in the conversation's storage and is separate from the AI audit journal.

The personal credential encryption key can be rotated: configure the new key with `rotation.previousEncryptionKey` carrying the old one, and during the dual-key window a read of an old-key credential re-encrypts it under the new key while new writes use it; failed decryptions and writes fail closed. A host that already owns a live namespace fence can proactively re-encrypt the whole plugin database through the rotation handle the installation wiring returns, which reports only inspected and rotated counts. The stock service exposes no maintenance fence — a public maintenance surface is future work — and rotation never touches other plugins' databases or returns credential values.

Hosts can evaluate health from the metrics subscriber — denial rate, lease contention, mean dispatch latency, and journal decision volume, each against a tunable threshold — as a pure, fail-open read that never gates dispatch, and can start a scheduled journal prune runner that applies the existing retention contract on an interval. Uncertainty records are committed before any deletion; deletes run in bounded chunks per transaction, so a large pass cannot starve a concurrent journal append on SQLite's single serialized writer; a failed pass is warned and retried at the next interval; stopping the runner awaits the in-flight pass. A stopped or failed pass reports zeros that mean "not measured", never "the journal holds none".

Tool servers register as modules on the stock service factory: each declared tool becomes a guarded, journaled dispatch mediated exactly like model dispatch — per-attempt permission, fence, and credential recheck, envelope validation against the final request, and only certified destination routes — using the server's scoped credential from the reserved `mcp:` namespace, which can never be reached through a model provider id. Each tool gets its own permission name under the same exact-name rule as models. The default factory registers none.

Usage accounting is host surface: hosts construct the reader over the audit journal — the decisions and outcomes already enforced per dispatch — and aggregate it into time-windowed, grouped reports. It adds no enforcement of its own and records no durations. Queries name session ids, or enumerate namespaces through a host-supplied enumerator; without one, a query that names no sessions fails closed with an actionable error rather than enumerating anything.

Model discovery reports canonical catalog descriptors — the identity pair plus adapter, type, context window, and output limit where the catalog entry carries them — filtered per pair by the caller's own credentials, through the existing models route as additive wire fields. The installation configuration now accepts `classifier` and `image` catalog entries in addition to `chat`, with each type's size fields following the pinned catalog shapes: a classifier requires its context window, an image entry carries none. The permission-name rule is documented for policy authors, including the decode algorithm back to the model pair and the literal-star edge: there is no wildcard syntax, and a name matches exactly one encoded pair or nothing.

Classification and image generation dispatch through certified provider modules like chat: TypeSafe System One and OpenAI Decisions for classification, and OpenRouter for image generation, each with its own envelope validation on the guarded transport — a dispatch that completes without a guarded send fails closed, and only certified route shapes are accepted. The audit journal's model attempt records carry decisions and outcomes and exclude image data; image blobs are never journaled. Image-bearing requests are bounded per request at the shared envelope cap, but persisted image history is a separate cost that the request cap does not bound: hosts enabling image attachments in higher layers must bound total persisted image bytes and history length themselves, because storage cost grows with the history.
