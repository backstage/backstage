`versions:bump` now writes each new version where the dependency is declared. In pnpm workspaces, `catalog:` references are updated in the default catalog of `pnpm-workspace.yaml` rather than replaced with version ranges, and `--catalog <name>` updates only the entries of that catalog, for example to keep a second release line. In Yarn projects, `catalog:` references are left as they are, with a warning, instead of being replaced with version ranges. When none of the Backstage dependencies are bumped, for example because they all refer to named catalogs, `versions:bump` changes nothing, including the release in `backstage.json` and the Backstage Yarn plugin. Versions are changed in place in `pnpm-workspace.yaml`, which keeps its comments and formatting. Adding an entry writes out the whole file, which keeps the comments but may change the formatting. A catalog belongs to the whole workspace, so bumping it also moves the packages outside of the Backstage installation that refer to it. When a Backstage dependency refers to a catalog that the workspace doesn't define, the command fails before it changes any files, and names the dependency. After a bump, moved packages are only migrated in the kind of dependency that the bump updates: version ranges and the default catalog, or with `--catalog <name>` only the references to that catalog. A moved package that the bump only updates in some of the dependency fields of a package is left as it is in that package, since its source code is migrated as a whole. Moved packages that refer to a catalog keep the reference, and the new package name gets an entry in that catalog. In a Backstage installation in a subdirectory of a pnpm workspace, `versions:bump` only bumps the packages of the installation. A warning lists the `overrides` in `pnpm-workspace.yaml` that pin bumped packages, since overrides take precedence over both version ranges and catalogs. An override that refers to a catalog or to a dependency of the root `package.json` only follows the bump when the bump updates what it refers to. Two new flags, `--dry-run` and `--json`, show the bumps without changing any files, and `--dry-run --json` prints the resolved versions for other tools to use.
